# Fantasy Football Matrix v1.6.1 Health Resilience Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prevent ESPN scoreboard failures from falsely downgrading an otherwise healthy Fantasy Football Matrix while preserving safe kickoff/lock timing and enforcing one runtime version authority.

**Architecture:** Keep nflverse as the required football-data backbone. Add nflverse `games.csv` as the required schedule/timing feed, retain ESPN only as optional live-score enrichment, and derive health status from required feeds rather than optional enrichment. Centralize the runtime version in one CommonJS module consumed by the app shell, health endpoint, nfl-data endpoint, and source policy; keep the root `VERSION` release marker synchronized by tests.

**Tech Stack:** Node.js 20 serverless functions, CommonJS, built-in `node:test`, GitHub Actions, Vercel deployment lock.

**Spec:** User-approved v1.6.1 Health Resilience hotfix in the September 11, 2026 project conversation.

## Global Constraints

- Work only on `hotfix-v1.6.1-health-resilience` until the user separately approves production release.
- Keep `vercel.json` with `git.deploymentEnabled:false`.
- Do not add or register a service worker.
- Preserve current v1.6.0 Season Intelligence behavior and rollback point.
- Do not fabricate schedule, kickoff, live score, or lock information when a source is unavailable.
- ESPN is optional enrichment; nflverse roster, performance, and schedule are required health inputs.
- Required schedule/timing failure must produce `DEGRADED`, not `LIVE`.
- Required roster failure remains `OFFLINE`; stale roster remains `STALE`.
- All versioned runtime request headers must use v1.6.1 through one authority.

- Produces: required schedule health metadata and `gameSchedule` entries with `id`, `kickoffAt`, `state`, and `teams`.

- [ ] **Step 1: Add schedule candidate to source policy**

Expose one nflverse schedule source under a stable `scheduleUrl`/schedule source descriptor, using the same CSV headers and timeout conventions as other nflverse feeds.

- [ ] **Step 2: Probe schedule in `/api/health`**

Schedule success is required for `LIVE`. Schedule failure returns `DEGRADED`; it does not make roster data `OFFLINE`.

- [ ] **Step 3: Parse schedule in `/api/nfl-data`**

Read `game_id`, `season`, `week`, `gameday`, `gametime`, `away_team`, and `home_team`. Build ISO-like kickoff timestamps only when both date and time parse safely. Never infer missing kickoff times.

- [ ] **Step 4: Preserve ESPN as optional enrichment**

Keep ESPN active-game events and live status when available. An ESPN error is exposed in payload metadata but must not independently downgrade overall health if required nflverse feeds are healthy.

- [ ] **Step 5: Keep lock safety fail-closed**

If schedule timing is unavailable for a player/team, downstream late-swap logic must continue treating that timing as unknown rather than assuming unlocked.
